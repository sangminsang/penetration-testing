## 1. Flask Application Context 의존성 문제

### 🚨 심각도: 높음

**문제**: 여러 파일에서 `current_app.config`를 사용하지만, Flask 애플리케이션 컨텍스트 외부에서 호출 시 `RuntimeError` 발생합니다.

### 영향받는 파일:

#### 1.1 `cve_client.py`
- **위치**: `app/cve_client.py`
- **문제 함수**:
  - `search_cves_by_service()` (line 13)
  - `get_cve_detail()` (line 47)
- **사용 예**:
  ```python
  base_url = current_app.config["CVE_SEARCH_BASE_URL"]
  ```
- **에러 발생 시나리오**: Flask 애플리케이션 컨텍스트 없이 독립적으로 함수 호출 시
- **에러 메시지**: `RuntimeError: Working outside of application context.`

#### 1.2 `ai_client.py`
- **위치**: `app/ai_client.py`
- **문제 함수**: `call_ollama()` (line 107-108)
- **사용 예**:
  ```python
  base_url = current_app.config["OLLAMA_BASE_URL"]
  model = current_app.config["OLLAMA_MODEL"]
  ```
- **에러 발생 시나리오**: 동일 (Flask 컨텍스트 외부 호출)

#### 1.3 `core/scenario/generator.py`
- **위치**: `app/core/scenario/generator.py`
- **문제 함수**: `call_ollama()` (line 121-122)
- **사용 예**:
  ```python
  base_url = current_app.config["OLLAMA_BASE_URL"]
  model = current_app.config["OLLAMA_MODEL"]
  ```
- **에러 발생 시나리오**: 동일

#### 1.4 `routes.py`
- **위치**: `app/routes.py`
- **문제 함수**: `api_scan()` (line 162-163)
- **사용 예**:
  ```python
  nmap_args=current_app.config["NMAP_ARGS"],
  mask=current_app.config.get("MASK_REAL_IP", True),
  ```
- **참고**: 이 파일은 Flask Blueprint 내부이므로 일반적으로 문제 없음

#### 1.5 `api/routes.py`
- **위치**: `app/api/routes.py`
- **문제 위치**:
  - line 568, 572-573: `current_app.config["NMAP_ARGS"]`
  - line 742: `current_app.config.get("DEBUG")`
- **참고**: Flask Blueprint 내부이므로 일반적으로 문제 없음

### 해결 방안:
1. **함수 파라미터로 config 전달**: Flask 컨텍스트 의존성 제거
2. **기본값 설정**: `current_app.config.get()` 사용 시 기본값 제공
3. **함수 분리**: Flask 의존 함수와 독립 함수 분리

## 2. 상대 경로 기반 파일 시스템 의존성

### 🚨 심각도: 중간

**문제**: 데이터베이스 및 캐시 파일 경로가 상대 경로로 지정되어 있어, 작업 디렉토리에 따라 다른 위치에 생성되거나 파일을 찾지 못할 수 있습니다.

### 영향받는 파일:

#### 2.1 `core/cve/cache_manager.py`
- **위치**: `app/core/cve/cache_manager.py`
- **문제**: line 25, 46
- **경로**: `"data/cve_cache.db"`
- **현재 처리**: `Path(db_path).parent.mkdir(parents=True, exist_ok=True)` (line 49)로 디렉토리 자동 생성
- **잠재적 문제**: 
  - 작업 디렉토리가 `app/`일 경우 → `app/data/cve_cache.db` 생성
  - 작업 디렉토리가 프로젝트 루트일 경우 → 프로젝트루트/data/cve_cache.db 생성
  - 실행 위치에 따라 다른 DB 파일을 참조할 수 있음

#### 2.2 `api/routes.py`
- **위치**: `app/api/routes.py`
- **문제**: line 46
- **경로**: `db_path="data/cve_cache.db"`
- **동일한 문제**: `CacheManager` 초기화 시 상대 경로 사용

### 해결 방안:
1. **절대 경로 또는 프로젝트 루트 기준 경로 사용**
2. **환경 변수 또는 설정 파일로 경로 지정**
3. **`__file__` 기반 상대 경로 계산**

## 3. Import 경로 분석

### ✅ 대부분 정상

프로젝트의 import 경로는 대부분 올바르게 구성되어 있습니다.

### 정상 작동하는 Import:

1. **상대 import (`api/routes.py`)**:
   ```python
   from ..core.recon.network import run_recon
   from ..core.cve.matcher import parse_complex_version_string
   from ..utils.exploit import search_exploits_for_cves
   ```
   - ✅ 정상: `app/api/routes.py` → `app/core/recon/network.py` ✓
   - ✅ 정상: `app/api/routes.py` → `app/utils/exploit.py` ✓

2. **상대 import (`routes.py`)**:
   ```python
   from .core.cve.matcher import parse_and_normalize_version
   ```
   - ✅ 정상: `app/routes.py` → `app/core/cve/matcher.py` ✓

3. **절대 import (matcher.py, async_nvd_client.py)**:
   ```python
   from app.config import Config
   ```
   - ✅ 정상: try-except로 처리되어 있음

### ⚠️ 주의가 필요한 Import:

#### 3.1 `main.py`
- **위치**: `app/main.py`
- **코드**: `from nvd_client import NvdClient` (line 2)
- **문제**: 상대 import가 아님
- **영향**: 
  - `app/` 디렉토리에서 실행 시: ✅ 정상 작동
  - 프로젝트 루트에서 실행 시: ❌ `ModuleNotFoundError` 가능성
- **해결 방안**: 
  ```python
  from .nvd_client import NvdClient  # 또는
  from app.nvd_client import NvdClient  # (프로젝트 루트 기준)
  ```

## 4. 선택적 의존성 처리

### ✅ 잘 처리됨

선택적 의존성(redis, pymysql, psycopg2, pymongo 등)은 대부분 try-except로 올바르게 처리되어 있습니다.

### 잘 처리된 예:

1. **`core/cve/cache_manager.py`** (line 69-70):
   ```python
   try:
       import redis
       self.redis_client = redis.Redis(...)
   except ImportError:
       ...
   ```

2. **`core/recon/database.py`**:
   - line 47: `pymysql` try-except
   - line 117: `psycopg2` try-except
   - line 173-174: `pymongo` try-except
   - line 238: `redis` try-except

3. **`core/cve/matcher.py`** (line 36-41):
   ```python
   try:
       from packaging import version
       VERSION_COMPARE_AVAILABLE = True
   except ImportError:
       VERSION_COMPARE_AVAILABLE = False
       logger.warning("packaging 모듈이 없어...")
   ```

**결론**: 선택적 의존성은 적절히 처리되어 있어, 해당 라이브러리가 없어도 기본 동작은 가능합니다.

## 5. 기타 잠재적 문제

### 5.1 Config Import 복잡성

**위치**: `core/cve/matcher.py`, `core/cve/async_nvd_client.py`

**코드**:
```python
project_root = Path(__file__).parent.parent.parent.parent
if str(project_root) not in sys.path:
    sys.path.insert(0, str(project_root))

try:
    from app.config import Config
except ImportError:
    try:
        import config
        Config = config.Config
    except ImportError:
        class Config:
            # 기본값...
```

**평가**: 
- ✅ 복잡하지만 동작함
- ⚠️ 파일 위치 변경 시 `parent.parent.parent.parent` 계산이 깨질 수 있음
- 💡 개선 가능: 더 명확한 경로 계산 방법 사용

### 5.2 Flask Blueprint 중복

**문제**: `routes.py`와 `api/routes.py` 모두 Blueprint를 정의하고 있음

**분석**:
- `app/routes.py`: `bp = Blueprint("main", __name__)`
- `app/api/routes.py`: `bp = Blueprint("main", __name__)`

**영향**: 
- 같은 이름의 Blueprint가 두 개 있음
- 실제 사용은 `__init__.py`에서 `api/routes.py`만 사용 중 (line 8-9)
- `routes.py`는 사용되지 않을 가능성

**권장**: 사용되지 않는 Blueprint는 제거하거나 이름 변경

### 5.3 데이터 디렉토리 존재 확인

**문제**: `data/` 디렉토리가 git에 포함되어 있는지 확인 필요

**현재 처리**: `cache_manager.py`에서 자동 생성 (line 49)

**평가**: ✅ 자동 생성으로 처리되어 있어 문제 없음
